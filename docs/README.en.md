# Agent artifacts

This directory stores artifacts generated by the AI agent pipeline described in [orchestration/ORCHESTRATION.md](./orchestration/ORCHESTRATION.md).

| Directory | Generating agent |
|---|---|
| `planning/` | Project Planner |
| `risk/` | Risk Analyst |
| `architecture/` | Solution Architect |
| `reviews/` | Implementation Reviewer, QA Production Lead |
| `test-strategy/` | Test Strategy Writer |
| `test-plans/` | Test Plan Writer |
| `manual-tests/` | Manual Test Designer |
| `automation/` | Automation Engineer |
| `reports/` | Retrospective Reporter |

The `reports/implementation-<slug>.md` report is created by **Documentation Curator** after the final review. It is a consolidated summary of the changes actually implemented, their evidence, and gaps.

File names contain the task `<slug>`, for example `plan-dark-mode.md`, to associate artifacts for the same task across directories.

## Self-documenting implementation

Every new feature should have a manifest at `docs/manifests/manifest-<slug>.json`. The manifest is a shared contract for the LLM orchestrator and the script verification gate: it stores the list of artifacts, their status (`pending`, `in-progress`, `complete`, `blocked`), changed implementation files, and update history.

Create documentation for a new task:

```bash
npm run docs:init -- --slug reminders --title "Reminders" --requirement "Requirement description" --source hybrid
```

The command creates the manifest, directories, and missing Markdown files with minimal sections. Existing files are preserved, so it is safe to run again when resuming a task.

After completing a stage, update the manifest and that stage's document:

```bash
npm run docs:update -- --slug reminders --artifact architecture --status complete \
	--summary "Added the reminder model and handling" --files src/types/reminder.ts,src/hooks/useReminders.ts
```

Validation checks the manifest version, slug consistency, statuses, and existence of all required artifacts:

```bash
npm run docs:validate
```

`npm run verify` performs this validation before linting and Playwright tests. The script checks structure and completeness; reviewing agents still assess whether the code substantively matches its description.

## Bilingual file convention

Polish files are the original documentation and remain unchanged. Every Markdown documentation and agent instruction file has an English counterpart beside it with the `.en.md` suffix, for example `plan-edycja-zadania.md` and `plan-edycja-zadania.en.md`. Links in this index continue to point to the Polish originals; use the matching `.en.md` file for English.
